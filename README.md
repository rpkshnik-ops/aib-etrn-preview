# Компания АиБ — лендинг ЭТрН

Полный проект: тёмный адаптивный лендинг, документы у формы, серверный приём заявок и доставка на **etrn@corp.aib.ru через ваш SMTP**. Телефон: **+7 961 777-02-20**. Сохранены НДС 5%, удалённый формат работ и согласованные эффекты.

- [Предпросмотр](https://rpkshnik-ops.github.io/aib-etrn-preview/)
- [Исходный код](https://github.com/rpkshnik-ops/aib-etrn-preview)

GitHub Pages — отдельный статический предпросмотр из `docs/`: там остаётся прежний канал FormSubmit. На Linux форма обращается к `/api/leads` на вашем сервере, а не к FormSubmit. Простого копирования `docs/` на сервер для работы SMTP **недостаточно**.

## 1. Подготовка сервера

Автоустановка рассчитана на **Ubuntu 24.04+ или Debian 12+ с systemd**, Python 3.11+, Nginx и права `sudo`. В CI установка проверяется на Ubuntu 24.04. Для другого Linux требуется адаптация пакетного менеджера и конфигурации Nginx; универсальная поддержка всех дистрибутивов не заявляется.

Нужны:

1. Домен и доступ к DNS. Запись A должна указывать на IPv4 сервера; если есть AAAA — на работающий IPv6 этого же сервера.
2. SSH и входящие TCP-порты 80/443. Не закрывайте SSH при изменении firewall. Порт 8081 открывать наружу не нужно.
3. Адрес SMTP, порт, режим TLS, логин и пароль/пароль приложения. Узнайте их у администратора корпоративной почты: установщик не угадывает настройки `corp.aib.ru`.
4. Разрешённый SMTP-сервером отправитель, по умолчанию `etrn@corp.aib.ru`. Получатель заявок фиксирован: `etrn@corp.aib.ru`.
5. Исходящий доступ к SMTP и HTTPS. При блокировке почтовых портов провайдером VPS запросите разблокировку.

На сервере с другими сайтами проверьте, что домен, порт 8081, службы `aib-etrn-*`, каталог `/opt/aib-etrn` и конфигурация Nginx `aib-etrn` не заняты. Установщик добавляет отдельный virtual host, не удаляет другие сайты, но перезагружает общий Nginx после проверки конфигурации. Сохраните резервную копию существующих настроек.

## 2. Установка

Подключитесь по SSH. Эти команды выполняются **на Linux-сервере**, не на локальном Windows-компьютере:

```bash
sudo apt-get update
sudo apt-get install -y git
sudo install -d -m 755 /opt/aib-etrn
sudo git clone https://github.com/rpkshnik-ops/aib-etrn-preview.git /opt/aib-etrn/repo
cd /opt/aib-etrn/repo
sudo bash deploy/install.sh
```

Каталог `/opt/aib-etrn/repo` должен отсутствовать перед `git clone`. Для существующей установки используйте раздел обновления. Репозиторий и виртуальное окружение принадлежат администратору; сервисный пользователь не может менять исполняемый код.

Установщик последовательно запросит:

| Параметр | Что ввести |
| --- | --- |
| Домен | Только имя, без `https://` и пути |
| Адрес SMTP | Имя сервера, без протокола и порта |
| TLS | `starttls` или `ssl` |
| Порт | Значение администратора; предлагается 587 для STARTTLS, 465 для SSL/TLS |
| Логин | Обычно полный email; `-` только для специально настроенного реле без авторизации |
| Пароль | Ввод скрыт: символы и звёздочки не показываются |
| Отправитель | Разрешённый почтовым сервером email |
| Проверочное письмо | При согласии отправляется техническое письмо на `etrn@corp.aib.ru` |
| Политика и согласие | HTTPS-ссылки на окончательные документы; можно пропустить для тестового запуска |
| Яндекс Метрика — необязательно | Цифровой ID счётчика; Enter — пропустить, `-` — отключить ранее настроенную аналитику |
| HTTPS | При готовом DNS можно сразу выпустить сертификат Let's Encrypt |

Enter принимает значение в квадратных скобках. `ssl` означает TLS с начала соединения; `starttls` — обязательное переключение на TLS **до авторизации**. Незащищённого режима нет, проверка сертификата включена. Названия режимов соответствуют [Python smtplib](https://docs.python.org/3/library/smtplib.html).

Пароль не передаётся в аргументах команд, HTML/JavaScript или GitHub. Он хранится в `/etc/aib-etrn/config.json`: права `0640`, владелец `root`, группа `aib-etrn`; права каталога `0750`. Доступ остаётся у администратора и приложения. Это защищённый правами файл, **не зашифрованное хранилище**. Не присылайте его в чат и не прикладывайте к отчётам.

Если SMTP-тест завершится ошибкой, прежняя конфигурация не заменяется. Исправьте параметры и повторите запуск. Если тест пропущен, доставку необходимо проверить отдельно. «SMTP-сервер принял письмо» не доказывает попадание во входящие: проверьте ящик, спам и ограничения почты.

Устанавливаются Nginx, служба `aib-etrn-api` (Gunicorn/Flask на `127.0.0.1:8081`) и `aib-etrn-worker` (обработчик SMTP). SQLite-очередь хранится в `/var/lib/aib-etrn/leads.sqlite3`, вне публичной папки.

Первый запуск — **staging**: дизайн и серверная форма работают, но страница помечена `noindex` до проверки доставки и документов. `noindex` не ограничивает доступ: сайт доступен по адресу. До анонса используйте только собственные тестовые данные.

## 3. HTTPS и проверка

Если сертификат был пропущен, после настройки DNS выполните, заменив домен:

```bash
sudo certbot --nginx --redirect -d etrn.company.ru
sudo certbot renew --dry-run
systemctl list-timers --all | grep certbot
```

Выбранная HTTP-01 проверка требует доступного порта 80; оставьте его доступным для продления. [Документация Certbot](https://eff-certbot.readthedocs.io/en/stable/using.html#nginx).

```bash
sudo systemctl status aib-etrn-api aib-etrn-worker nginx --no-pager
curl --fail https://etrn.company.ru/healthz
cd /opt/aib-etrn/repo
sudo bash deploy/manage.sh status
sudo bash deploy/manage.sh smtp-test
```

Последняя команда **отправляет реальное техническое письмо**. `/healthz` должен вернуть `{"status":"ok"}`. Он проверяет очередь и обработчик, но не подключается к SMTP при каждом запросе и не подтверждает доставку конкретного письма.

Откройте сайт по HTTPS на компьютере и телефоне. Отправьте форму со своими тестовыми данными и согласием. Проверьте получение письма на `etrn@corp.aib.ru`, корректность полей и открытие обоих PDF без сброса формы. На HTTP отправка намеренно не проходит проверку источника.

## 4. Финальная публикация и документы

[Оферта](src/assets/documents/offer.pdf) и [соглашение о конфиденциальности](src/assets/documents/confidentiality.pdf) уже включены в `src/assets/documents/` и представлены заметными ссылками у формы и в подвале. PDF подготовлены из документов владельца от 23.09.2026 с проверкой сохранения текста. При переносе на сервер содержание документов не переписывалось.

Чеклист владельца перед публичным запуском:

- [ ] Подтвердить домен, DNS, HTTPS и корпоративный SMTP.
- [ ] Получить реальную заявку с серверной формы в нужном ящике.
- [ ] Проверить окончательную редакцию оферты: в предоставленном документе есть незаполненная дата и контакты, отличающиеся от контактов лендинга.
- [ ] Предоставить окончательные политику обработки персональных данных и текст согласия. Соглашение о конфиденциальности не используется вместо этих документов.
- [ ] Проверить соответствие документов фактическому процессу обработки заявок.
- [ ] Настроить мониторинг `/healthz`, резервное копирование и проверку продления сертификата.

Можно разместить утверждённые документы на другом HTTPS-сайте либо в `/srv/aib-etrn/legal/`:

```bash
sudo install -m 644 /path/to/privacy.pdf /srv/aib-etrn/legal/privacy.pdf
sudo install -m 644 /path/to/consent.pdf /srv/aib-etrn/legal/consent.pdf
```

Замените `/path/to/...` реальными путями. Документы будут доступны по `https://ВАШ-ДОМЕН/legal/privacy.pdf` и `.../consent.pdf`; каталог не перезаписывается при обновлении статики.

```bash
sudo nano /opt/aib-etrn/repo/site.local.json
```

Пример настроек **после** получения письма и подключения окончательных документов, со своим доменом:

```json
{
  "mode": "production",
  "site_url": "https://etrn.company.ru/",
  "privacy_url": "https://etrn.company.ru/legal/privacy.pdf",
  "consent_url": "https://etrn.company.ru/legal/consent.pdf",
  "offer_url": "https://etrn.company.ru/assets/documents/offer.pdf",
  "delivery_confirmed": true,
  "metrica_id": ""
}
```

```bash
cd /opt/aib-etrn/repo
sudo bash deploy/update.sh
curl --fail https://etrn.company.ru/robots.txt
curl --fail https://etrn.company.ru/sitemap.xml
```

В production исчезают пометка предпросмотра и проект условий, появляются разрешение индексации, canonical и sitemap. Сборка требует ссылки и `delivery_confirmed: true`, но не проверяет юридическую корректность или доступность документов — откройте ссылки вручную. Метрика отключена по умолчанию; `metrica_id` заполняется только при принятом решении подключить аналитику и соответствующей подготовке документов.

### Необязательная настройка Яндекс Метрики

Установщик просит **только цифровой ID счётчика** (5–12 цифр), например `12345678`. Пароль Яндекса, OAuth-токен и HTML-код счётчика не нужны. Счётчик создаётся владельцем для своего домена в интерфейсе Метрики: [официальная инструкция Яндекса](https://yandex.ru/support/metrica/ru/general/creating-counter).

- При первой установке нажмите **Enter**, чтобы пропустить шаг: сайт и заявки работают без аналитики, скрипт Метрики не загружается.
- При повторной настройке Enter сохраняет прежний ID, показанный в квадратных скобках.
- Чтобы заменить счётчик, введите новый ID. Чтобы отключить — введите `-`.
- Некорректный ID не прерывает установку: можно исправить ввод либо пропустить шаг.

Значение сохраняется в `site.local.json`, поле `metrica_id`. В `staging` и `preview` счётчик **не загружается даже при заполненном ID**, чтобы тесты не попадали в статистику. После перехода в `production` и пересборки он подключается автоматически. Существующий скрипт не включает Вебвизор и не передаёт контакт или описание заявки в параметры целей; перед включением аналитики проверьте документы по обработке данных.

Подключить, заменить или отключить Метрику позже, без повторного ввода SMTP:

```bash
cd /opt/aib-etrn/repo
sudo bash deploy/install.sh --analytics-only
```

Команда запрашивает ID и пересобирает/публикует страницу, сохраняя текущий режим сайта. SMTP, очередь и остальные настройки не меняются. На уже установленном сервере сначала обновите код через `sudo git pull --ff-only`, если в вашей версии ещё нет этого режима. Обычный `deploy/update.sh` сохраняет настроенный ID.

В production проверьте статус счётчика в Метрике и отсутствие блокировщика аналитики в тестовом браузере. Установщик проверяет формат ID, но не доступ к счётчику и не получение событий Яндексом. Сайт отправляет события `cta_click`, `form_start`, `form_error`, `lead_accepted`, `contact_click`; нужные цели с такими идентификаторами настраиваются владельцем в интерфейсе Метрики, установщик не создаёт их в аккаунте.

## 5. Смена SMTP

```bash
cd /opt/aib-etrn/repo
sudo bash deploy/install.sh --smtp-only
```

Повторно вводятся адрес, TLS, порт, логин, пароль и отправитель. Enter в поле пароля сохраняет прежний пароль при неизменном логине. Домен, сайт и очередь не меняются; службы перезапускаются. После смены пароля в почтовой системе обновите его здесь.

После исправления настроек верните сохранённые неотправленные заявки в очередь:

```bash
sudo bash deploy/manage.sh retry-failed
sudo bash deploy/manage.sh status
```

`retry-failed` повторно отправляет неуспешные заявки; после истечения срока хранения восстановить их этой командой нельзя.

## 6. Доставка и диагностика

Заявка сохраняется в SQLite **до** ответа об успешном приёме; отправляется отдельно. Временные ошибки: до 8 попыток с увеличением паузы. Ошибки авторизации, сертификата, запрета получателя или поддержки TLS сразу требуют вмешательства.

`sent` означает приём SMTP-сервером, не прочтение или попадание во входящие. При обрыве после приёма письма возможен повтор; номер заявки и Message-ID одинаковы. Абсолютная гарантия отсутствия повторов через SMTP не заявляется.

Содержимое отправленной заявки удаляется из рабочей очереди, служебный статус остаётся до очистки. Недоставленные заявки хранятся 7 дней от создания и удаляются ежечасной очисткой (допуск до часа при работающем обработчике). Почта и резервные копии имеют отдельные сроки хранения, определяемые администратором. Следите за сбоями ежедневно.

```bash
sudo journalctl -u aib-etrn-api -u aib-etrn-worker --since '1 hour ago' --no-pager
sudo bash /opt/aib-etrn/repo/deploy/manage.sh status
sudo nginx -t
```

Приложение не пишет пароль, контакт или описание заявки в штатные логи. Не включайте SMTP debug и не публикуйте конфигурацию/базу. Есть ограничения размера запроса, частоты заявок с IP и размера очереди, проверка источника, согласия, контакта, антиспам-поле и защита от повторного запроса. Это базовая защита, не замена внешней защите от DDoS.

| Признак | Что проверить |
| --- | --- |
| `smtp_authentication_failed` | Логин, пароль приложения, разрешение SMTP AUTH |
| `smtp_certificate_invalid` | Имя сервера, системное время, цепочку сертификата; не отключайте TLS-проверку |
| `smtp_tls_or_auth_not_supported` | Порт, режим и методы авторизации сервера |
| `smtp_recipient_refused` / `smtp_response_...` | Получателя, разрешённого отправителя и почтовые лимиты |
| `smtp_unavailable` | DNS, firewall, блокировку порта провайдером |
| HTTP 429 | Лимит частоты; дождитесь его сброса |
| HTTP 503 / `degraded` | Остановленный обработчик, ошибки доставки, ожидание в очереди более 10 минут |
| Письма нет после приёма SMTP | Спам/карантин, фильтры, логи почты, SPF/DKIM/DMARC у почтового администратора |

## 7. Резервные копии

Базу и секреты храните вне репозитория/публичного каталога. Копии содержат персональные данные и секреты: ограничьте доступ, используйте шифрованное внешнее хранилище и согласованный срок хранения.

Согласованный снимок SQLite без остановки:

```bash
sudo install -d -o aib-etrn -g aib-etrn -m 700 /var/lib/aib-etrn/backups
sudo bash /opt/aib-etrn/repo/deploy/manage.sh backup --output /var/lib/aib-etrn/backups/leads-2026-09-23.sqlite3
```

Каждый раз выбирайте новое имя: существующий файл не перезаписывается. Отдельно сохраните `/etc/aib-etrn/config.json`, `/etc/aib-etrn.env`, `site.local.json`, `/srv/aib-etrn/legal/`, настройки Nginx/сертификатов и текущий commit. Автоматической выгрузки копий во внешнее хранилище нет.

Для восстановления остановите обе службы. Сохраните текущую базу вместе с её `-wal`/`-shm` в отдельную копию. Восстановите проверенный SQLite-снимок как `/var/lib/aib-etrn/leads.sqlite3`, владелец `aib-etrn:aib-etrn`, права `0600`, без `-wal`/`-shm` от другой версии базы. Восстановите конфигурацию/права, запустите службы и проверьте `/healthz`. Не заменяйте базу на ходу. Восстановленная очередь может повторно отправить письма, принятые после даты снимка.

## 8. Обновление и откат

Сделайте резервные копии и запишите текущий commit:

```bash
cd /opt/aib-etrn/repo
sudo git status --short
sudo git rev-parse HEAD
sudo git pull --ff-only
sudo bash deploy/update.sh
```

Не продолжайте поверх непонятных локальных изменений и не применяйте принудительный сброс. Настройки `site.local.json` и SMTP игнорируются Git. Скрипт собирает сайт, проверяет Nginx, атомарно переключает ссылку на комплект статики, перезапускает службы. Возможна короткая недоступность формы при перезапуске API. Повторите проверки раздела 3.

Старые статические версии остаются в `/srv/aib-etrn/releases/`. Откат только HTML/CSS/JS:

```bash
sudo ls -1 /srv/aib-etrn/releases
sudo bash deploy/rollback.sh /srv/aib-etrn/releases/ИМЯ-ПРЕДЫДУЩЕЙ-ВЕРСИИ
```

Он не откатывает API, зависимости, базу или `/legal/`. Для полного отката выберите записанный commit (`sudo git switch --detach COMMIT`) и запустите `sudo bash deploy/update.sh`; сначала проверьте совместимость базы и сделайте снимок. Возврат к основной ветке: `sudo git switch main`. Старые релизы и копии не удаляются автоматически — контролируйте место.

## 9. Структура и разработка

```text
src/                    страница, стили, JavaScript и PDF
backend/                API, SMTP, очередь, обслуживание
deploy/install.sh       установка; --smtp-only / --analytics-only
deploy/configure.py     скрытый ввод пароля, настройка служб и HTTPS
deploy/update.sh        сборка и публикация обновлений
deploy/publish.sh       атомарная публикация статики
deploy/rollback.sh      откат статики
deploy/manage.sh        очередь и SMTP-тест
docs/                   предпросмотр GitHub Pages
tests/                  проверки, SMTP только на loopback
.github/workflows/      CI на Ubuntu
README.md               эта инструкция
```

Локальные проверки:

```bash
python3 -m venv .venv
. .venv/bin/activate
python -m pip install -r requirements-dev.txt
python -m unittest discover -s tests -v
python build.py --mode preview
python -m playwright install chromium

```

В другом терминале с тем же окружением:

```bash
python browser_check.py

```

Windows: используйте `python`, `.venv\Scripts\Activate.ps1`; сервер устанавливается на Linux. Браузерные тесты подменяют ответ формы, не отправляя внешнюю почту. Ручная отправка в preview обращается к FormSubmit. Для обновления Pages пересоберите `python build.py --mode preview --output docs`, закоммитьте `docs/`; источник Pages — ветка `main`, папка `/docs`.

Тесты проверяют очередь/повторы/очистку, валидацию, ввод и сохранение SMTP-настроек, локальные соединения STARTTLS и TLS/SSL, адаптивность, PDF, необязательность Метрики, замену/отключение ID и отсутствие аналитики в тестовых сборках. CI дополнительно проверяет Nginx и запуск служб/конфигуратора на Ubuntu. Это не заменяет проверку вашего DNS, сертификата, доставки через корпоративный SMTP и получения событий вашим счётчиком после установки.

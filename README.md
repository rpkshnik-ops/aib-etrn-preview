# Компания АиБ — PHP 8.3 / 1С-Битрикс: Управление сайтом

Актуальная серверная версия лендинга — шаблон сайта **`aib_etrn`** для установленной CMS **«1С-Битрикс: Управление сайтом»**, PHP **8.3**. Заявки принимает **штатный `bitrix:form.result.new`**, изменён только его шаблон. Ядро CMS, код компонента, обработчики сохранения и правила проверки данных не копируются и не модифицируются.

Сохранены тёмный дизайн, круглый логотип, мобильная закреплённая кнопка, выбор симптома, анимации/FAQ, документы рядом с согласием, цена 130 000 ₽, НДС 5%, удалённые работы, телефон +7 961 777-02-20 и почта etrn@corp.aib.ru. Метрика необязательна.

**Предыдущие Python API/SQLite/SMTP и FormSubmit не участвуют в работе Bitrix-версии.** Инструкция v1.x сохранена в [README_LEGACY.md](README_LEGACY.md). GitHub Pages остаётся статическим предпросмотром старого варианта: он не исполняет PHP и не демонстрирует серверную работу Битрикса.

## 1. Требования

- Linux, **PHP 8.3** для веб-сервера и CLI. Убедитесь, что `php -v` и PHP-FPM/Apache используют одну требуемую ветку; проект не переключает системную версию PHP автоматически.
- Уже установленная, обновлённая и лицензированная «1С-Битрикс: Управление сайтом», совместимая с PHP 8.3, в кодировке UTF-8.
- Установленный модуль **«Веб-формы» (`form`)** и системный компонент `bitrix:form.result.new`. Проверьте наличие модуля в своей лицензии; редакция «Старт» не подходит для этого компонента. [Документация компонента](https://dev.1c-bitrix.ru/user_help/components/services/web_forms/form_result_new.php).
- База, расширения PHP и настройки окружения по [техническим требованиям CMS](https://www.1c-bitrix.ru/products/cms/requirements.php). Установщик шаблона не устанавливает CMS, не покупает лицензию, не создаёт базу и не обновляет ядро.
- Рабочие DNS/HTTPS, резервная копия файлов **и базы**, доступ администратора CMS. Тестовый стенд до установки в production обязателен.

Ни пароль администратора, ни ключ лицензии, ни SMTP-пароль не нужно передавать в чат или GitHub.

## 2. Что входит в проект

```text
bitrix/
  install.php                            CLI-развёртывание с резервной копией
  settings.example.php                   пример конфигурации
  robots.staging.txt                     запрет обхода тестового сайта
  site/                                  только файлы нашего решения
    index.php                            /bitrix/header.php → IncludeFile → footer.php
    .section.php                         свойства раздела
    robots.txt                           правила production с учётом Bitrix
    include/aib/                         редактируемые области лендинга
    upload/aib-etrn/documents/            оферта и соглашение PDF
    local/templates/aib_etrn/
      header.php                         ShowHead, ShowTitle, ShowPanel, Asset
      footer.php                         IncludeFile подвала, закрытие страницы
      description.php                    описание шаблона в админке
      styles.css, template_styles.css    стили редактора и публичной части
      assets/                            интерфейс, анимации, логотип
      lib/settings.php                   настройки представления
      components/bitrix/form.result.new/aib_etrn/template.php
```

В поставке **нет `/bitrix/`**, `component.php`, `result_modifier.php`, своего обработчика POST, SQL или `CFormResult::Add`. Отправка выполняется обычным POST компонента; AJAX намеренно выключен. Используются его `FORM_HEADER`, `FORM_FOOTER`, `QUESTIONS[*].HTML_CODE`, системные скрытые поля, CAPTCHA, расширенные ошибки и сообщение результата. Имена полей/значения ответов не подменяются.

`ShowHead()` выводит ресурсы и метаданные CMS, `ShowTitle()` поддерживает заголовки страницы, `ShowPanel()` — панель администратора. Блоки подключаются через `IncludeFile` и доступны в режиме правки. [ShowHead](https://dev.1c-bitrix.ru/api_help/main/reference/cmain/showhead.php), [IncludeFile](https://dev.1c-bitrix.ru/api_help/main/reference/cmain/includefile.php), [ShowPanel](https://dev.1c-bitrix.ru/api_help/main/reference/cmain/showpanel.php).

Страница использует `BX_COMPOSITE_SKIP` и `CACHE_TYPE=N`: форму с сессией/CAPTCHA нельзя отдавать из общего HTML-кеша. Не включайте внешний full-page cache для этой страницы без отдельной интеграции динамической формы.

## 3. Создание веб-формы в CMS

В админке откройте **Сервисы → Веб-формы**. Создайте форму, например `AIB_ETRN`, привяжите к нужному сайту. Если форма уже создана, используйте её ID и существующие вопросы; символьные коды можно сопоставить в конфигурации шаблона. Номера ответов не нужно прописывать в PHP/JavaScript.

Рекомендуемая структура:

| SID вопроса | Подпись | Тип ответа | Обязательность и ограничения |
| --- | --- | --- | --- |
| `CONTACT` | Телефон или email | `text` | Обязательный, предельная длина 254 |
| `NAME` | Имя | `text` | Необязательный, до 80 символов |
| `COMPANY` | Компания | `text` | Необязательный, до 120 символов |
| `PROBLEM` | Что происходит? | `textarea` | Обязательный, 20–1500 символов |
| `CONSENT` | Согласие на обработку данных | `checkbox`, один вариант «Согласен…» | Обязательный, без заранее выбранного ответа |

**Контакт — одно обязательное поле «Телефон или email».** Это позволяет использовать штатную обязательность вопроса без условных серверных обработчиков «одно из двух полей». Отдельного переключателя телефона/email в Bitrix-шаблоне нет. Формат контакта и диапазоны длины настройте доступными валидаторами вашей версии модуля; если нужны более строгие правила, согласуйте их с администратором CMS. Шаблон сам не добавляет серверные валидаторы и не обещает проверку, которая не включена в форме.

Важно:

1. Обязательность задавайте у **вопроса в Битриксе**, а не только HTML-атрибутом `required`.
2. Серверные ограничения длины/формата задавайте в настройках валидаторов вопроса. `maxlength` и другие параметры поля — лишь удобство браузера, их можно обойти. [Валидаторы форм](https://dev.1c-bitrix.ru/api_help/form/classes/cformvalidator/index.php).
3. Включите CAPTCHA для публичной формы, настройте штатную защиту/ограничения CMS. Не переносите автоматически обещания rate limit и идемпотентности старого Python API: у новой формы ограничения определяются настройками Битрикса.
4. Разрешите гостям **заполнение формы**, но не просмотр/редактирование чужих результатов. Доступ сотрудников к результатам настройте отдельно.
5. Установите сортировку вопросов, `CONSENT` последним. Перед ним шаблон выведет оферту и соглашение. Все дополнительные вопросы штатной формы также отображаются.
6. Вопрос `PROBLEM` должен иметь тип `textarea`, чтобы кнопки «Добавить в заявку» заполняли описание. При другом SID измените `field_sids.problem`.
7. Запишите числовой ID формы — его запросит установщик. Параметр `WEB_FORM_ID` берётся из серверной конфигурации, не из `$_REQUEST`.

## 4. Установка файлов

Сначала сделайте полную резервную копию CMS и базы. Проект размещайте **вне DOCUMENT_ROOT**: не публикуйте `.git`, тесты и установщик через веб-сервер. Команды выполняйте от пользователя, которому принадлежат файлы сайта; не меняйте владельца всего сайта на root.

```bash
git clone https://github.com/rpkshnik-ops/aib-etrn-preview.git /home/www/aib-etrn-release
cd /home/www/aib-etrn-release
php -v
php bitrix/install.php --root=/home/www/site-h7n
```

`/home/www/site-h7n` здесь — **пример DOCUMENT_ROOT установленного Битрикса**, а не путь к отдельному PHP-файлу. Замените его реальным путём. Если каталог клона уже есть, не клонируйте поверх: проверьте изменения и обновите через `git pull --ff-only`. Для архива распакуйте его вне web-root и запустите тот же `bitrix/install.php`.

Установщик запросит:

- Домен без протокола и пути (для кириллицы — Punycode).
- ID существующей веб-формы.
- Ссылки на политику и текст согласия: HTTPS URL или путь `/legal/...`; для staging можно пропустить.
- Режим `staging`/`production`; первый запуск — staging.
- **Необязательный ID Яндекс Метрики:** Enter пропускает или сохраняет прежний, `-` отключает.
- Явное подтверждение `yes` перед изменением файлов.

Файлы существующего решения (`index.php`, `robots.txt`, `.section.php`, наши шаблон/включаемые области) будут заменены только после подтверждения. Установщик заранее сохраняет заменяемые файлы и `manifest.json` в каталог `aib-etrn-backup-ДАТА-СУФФИКС` рядом с DOCUMENT_ROOT, **вне публичного каталога**, права 0700. Можно указать другой существующий закрытый каталог:

```bash
php bitrix/install.php --root=/home/www/site-h7n --backup-dir=/home/www/private-backups
```

Это резервная копия только затронутых файлов, **не базы и не всей CMS**. Установщик отказывается писать через символические ссылки. Он не меняет `/bitrix/`, `init.php`, `.settings.php`, Nginx/Apache, сертификаты, базу, SMTP или шаблоны других сайтов. Все записи файлов выполняются по одному; общей транзакции развёртывания нет — проводите установку в согласованное окно обслуживания.

После копирования:

1. В CMS: **Настройки → Настройки продукта → Сайты → Список сайтов → нужный сайт → Шаблоны**. Назначьте `aib_etrn` для главной страницы. Для существующего многостраничного сайта используйте условие назначения только нужной страницы, не заменяйте шаблон всех разделов вслепую.
2. Проверьте `/local/php_interface/aib_etrn.php`, ID формы и её привязку к сайту.
3. Очистите штатный кеш CMS; при отключённой проверке времени изменения файлов обновите OPcache штатным способом сервера.
4. Убедитесь, что корневой `index.html` старого лендинга не перехватывает запрос вместо `index.php`. Установщик его не удаляет: сохраните файл/переместите после проверки либо настройте приоритет `index.php`.
5. Откройте сайт как гость и администратор. Стилистика страницы не должна затрагивать панель CMS.

Если нужно разместить лендинг не в корне, а, например, в `/request/`, адаптируйте расположение `index.php`, canonical и условие назначения шаблона. Текущая поставка рассчитана на корень отдельного сайта/поддомена.

## 5. Почта и результаты заявок

Получатель уведомлений — **etrn@corp.aib.ru**. Настройте у формы её почтовый шаблон/почтовое событие и отправителя, разрешённого корпоративной почтой. Письмо должно включать контакт, имя, компанию, описание, согласие и номер результата. SMTP/транспорт настраивается средствами установленного Битрикса и почтового окружения сервера, не через старый Python-установщик.

Сам шаблон **не вызывает** `mail()`, `CEvent::Send()` и не записывает результат повторно. Сохранение, проверка и почтовые события остаются в штатном модуле. Сообщение об успешном сохранении результата не подтверждает доставку email — проверьте и результат в админке, и письмо в ящике. Настройте обработку очереди почтовых событий/агентов согласно конфигурации своего сервера.

Сроки хранения результатов, очистка, доступ сотрудников, резервное копирование БД и антиспам теперь определяются в CMS. Старые «7 дней в SQLite» и самостоятельные SMTP-повторы к этой версии не относятся.

## 6. Конфигурация и Метрика

Настройки хранятся в `/local/php_interface/aib_etrn.php`. Образец: [settings.example.php](bitrix/settings.example.php). Это файл представления, без SMTP-паролей/лицензионных ключей. При включении production должны быть заполнены домен, ID формы, политика и согласие.

Для другой структуры формы задайте соответствие ролей реальным SID:

```php
'field_sids' => [
    'contact' => 'CONTACT', 'name' => 'NAME', 'company' => 'COMPANY',
    'problem' => 'PROBLEM', 'consent' => 'CONSENT',
],
```

Метрика по-прежнему необязательна. Нужен только цифровой ID (5–12 цифр), не пароль или OAuth-токен. В staging скрипт не загружается даже с заполненным ID. Для изменения только аналитики:

```bash
php bitrix/install.php --root=/home/www/site-h7n --analytics-only
```

Enter сохраняет прежнее значение, `-` отключает. Создаётся резервная копия конфигурации; ядро, веб-форма и почта не меняются. После смены ID сбросьте кеш/OPcache при необходимости. Настройте нужные цели `cta_click`, `form_start`, `form_error`, `lead_accepted`, `contact_click` в своём счётчике; данные полей не передаются в параметры целей, Вебвизор не включается. Получение событий проверяется отдельно в реальной Метрике.

## 7. Документы и robots.txt

PDF оферты и соглашения доступны рядом с согласием и в подвале, открываются в новой вкладке. Политика обработки данных и текст согласия подключаются отдельно — соглашение о конфиденциальности их не заменяет. До публичного запуска подтвердите окончательные редакции, даты и контакты документов.

Для production подготовлен [robots.txt](bitrix/site/robots.txt): закрыты служебные разделы CMS, личный кабинет и управляющие параметры; открыты CSS/JS/изображения, нужные для отображения лендинга, и публичные PDF. Каталог `/bitrix/cache/` целиком не открывается — только CSS/JS. `robots.txt` **не защищает** личные данные: права CMS и веб-сервер должны запрещать неавторизованный доступ независимо от поисковых роботов.

В staging установщик публикует `Disallow: /` и метатег `noindex`. Для production повторите установку с режимом production или согласованно измените настройку и robots вручную. На существующем многостраничном сайте **объедините правила с текущими**, иначе staging-запрет закроет от обхода и другие страницы. Сгенерируйте sitemap средствами CMS, проверьте реальный URL и только затем добавьте строку `Sitemap: https://ВАШ-ДОМЕН/sitemap.xml`. Не публикуйте пример домена. [Генератор robots.txt Битрикса](https://dev.1c-bitrix.ru/learning/course/?COURSE_ID=139&LESSON_ID=5814&LESSON_PATH=11427.4545.5814).

## 8. Обновление, редактирование и откат

Редактируйте блоки через режим правки CMS (`/include/aib/`) либо в исходном проекте. Перед обновлением **сверьте эти изменения**: установщик не объединяет PHP/HTML и может заменить отредактированную область своей версией после подтверждения. В репозитории файлы дизайна экспортируются командой `python build_bitrix.py`; на сервере Python для работы сайта не нужен.

Для обновления: резервная копия файлов/БД → `git pull --ff-only` в каталоге исходников → сравнение изменённых областей → повторный запуск PHP-установщика → очистка кеша → проверки ниже. Не используйте `deploy/update.sh` или Nginx/systemd-файлы старой архитектуры.

Для отката используйте `manifest.json` созданной копии: восстановите файлы из списка `replaced`, а файлы из `created` убирайте только если они всё ещё принадлежат этому развёртыванию и не изменены позже. Восстановите прежнее назначение шаблона в настройках сайта, очистите кеш/OPcache. Базу из-за установки файлов откатывать автоматически не нужно — она не менялась; результаты заявок должны сохраняться.

При миграции с v1.x сначала завершите доставку старой SQLite-очереди и сохраните её резервную копию; только после проверки новой формы выводите из эксплуатации прежние службы. Установщик ничего из старой очереди не удаляет и не импортирует.

## 9. Проверки перед запуском

- [ ] PHP веб-сервера и CLI — 8.3, UTF-8, CMS и модуль `form` установлены/обновлены.
- [ ] Назначен шаблон, работают панель CMS, заголовок/описание и редактируемые области.
- [ ] У гостя есть право заполнения, но нет доступа к чужим результатам.
- [ ] Пустой контакт/описание, снятое согласие, неправильная CAPTCHA и серверные валидаторы отклоняются **штатным компонентом**, в том числе при прямом POST в обход JavaScript.
- [ ] Сессия/CSRF проверяются CMS; повторный клик не создаёт лишних отправок. Повторную загрузку POST и ограничения повторов проверьте отдельно в вашей конфигурации.
- [ ] После ошибки данные сохранены, ошибки читаемы, после успешного POST результат появился в админке.
- [ ] Получено письмо на `etrn@corp.aib.ru`; запись результата и доставка письма проверены отдельно.
- [ ] Работают CAPTCHA, документы, кнопки выбора симптома, FAQ, мобильная вёрстка 320/390/768 px и desktop.
- [ ] Метрика пропускается без влияния на форму, нужный счётчик работает в production.
- [ ] robots/canonical/sitemap соответствуют реальному домену и стадии запуска.
- [ ] Проверены политика, согласие, оферта, резервные копии, доступ к результатам и сроки хранения.

Автотесты проекта проверяют синтаксис PHP 8.3, контракт шаблона на тестовых данных, сохранение имён полей/сессии/CAPTCHA, обычный POST без собственного API, состояния формы, адаптивность, установщик и отсутствие изменений ядра. **Это не тесты лицензированного ядра Битрикса**: в CI используется явно обозначенная заглушка данных компонента без базы и реальной почты. Полный интеграционный прогон с вашим модулем/формой/валидаторами выполняется на стенде CMS по чеклисту выше.

Команды разработчика:

```bash
python build_bitrix.py
PHP_BINARY=/usr/bin/php8.3 python -m unittest tests.test_bitrix -v
python -m pip install playwright==1.58.0
python -m playwright install chromium
PHP_BINARY=/usr/bin/php8.3 python bitrix_browser_check.py
```
